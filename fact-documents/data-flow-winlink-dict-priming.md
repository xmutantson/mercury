# Data-flow audit — Winlink dictionary priming of the streaming compression context

Status: LIVE. Created 2026-06-12 (branch `feat/winlink-dict`, off the segfault
fix `fix/compress-ppmd-warm-segfault @ 1f01d10`).

This document covers the shared state introduced/extended by the Winlink-boilerplate
priming dictionary: the streaming compression context (PPMd model + zstd prefix)
and the new dict-version tag carried in the streaming header. It is the CLAUDE.md
§"Cross-Layer Data-Flow Audits" record for this change.

The lever (scope: `_research/WINLINK_DICT_SCOPE.json`): real Winlink SMALL messages
(300-3000 B) only hit 1.4-2.0x cold, where Mercury LOSES to VARA on real traffic
(cold aggregate edge 1.148 < the 1.63 VARA wire advantage). Seeding the streaming
context with a static Winlink-boilerplate dictionary lifts them to warm-bulk levels
(primed aggregate edge 1.664 > 1.63 → BEAT). VARA/LZHUF is structurally cold per
message (space-filled 2 KB window, no dict-inject API), so the primed edge is
uncontested.

## §1. What the priming does (mechanism)

`cl_compressor::prime_with_dict()` (source/compression/mercury_compress.cc),
called from `streaming_enable()` when `dict_priming_enabled`:

1. `decompress_block(WINLINK_DICT_COMPRESSED)` — a single deterministic forward
   pass of the baked dict symbols through the SHARED PPMd model (PPMd8 uses one
   model object for both enc and dec). Output sinks into `workspace`.
2. `streaming_commit(WINLINK_DICT_RAW)` — loads the raw dict into the zstd prefix
   (32 KB back-reference window) and sets `ppmd_model_warm`.

Both peers (TX commander, RX responder, and vice versa) call the SAME
`streaming_enable()` and run the IDENTICAL sequence on the IDENTICAL firmware-baked
bytes → the PPMd model + zstd prefix end in the SAME state on both sides. This is
the role-independent design: priming does not depend on whether the compressor will
next compress (TX) or decompress (RX).

The two baked artifacts (source/compression/winlink_dict.cc, generated by
tools/gen_winlink_dict.cc from tools/winlink_dict_v1.txt):
- `WINLINK_DICT_RAW[]`        — ~~1747 B~~ **2643 B** raw dictionary plaintext
  (v1 ENRICHED 2026-06-14 with standard-form boilerplate — see §9).
- `WINLINK_DICT_COMPRESSED[]` — ~~938 B~~ **1303 B**, the canonical
  streaming-compressed form of RAW produced by the production cl_compressor on a
  fresh **UN-PRIMED** stream. The generator self-checks `decompress(COMPRESSED) ==
  RAW` so a firmware linking the .cc is guaranteed self-consistent.

**Generator-priming bug fixed in the enrichment (load-bearing):** `prime_with_dict`
decodes `WINLINK_DICT_COMPRESSED` on a brand-new, NOT-yet-primed stream (priming is
the first thing `streaming_enable` does — mercury_compress.cc:241/269). Therefore
the canonical COMPRESSED blob MUST be the compression of RAW on a fresh **un-primed**
stream. `gen_winlink_dict.cc` previously left `set_dict_priming` default-ON, so on a
REGENERATION (when a non-empty dict is already linked) it seeded its context with the
PREVIOUSLY-baked dict before compressing → the blob round-tripped only against an
identically-primed RX, never the firmware's fresh prime path (`[DICT] Prime decode
failed (d=-1)` → dict silently stays cold, zero lift, fail-safe-but-useless). The
original 1747 B v1 dodged this only because it was the BOOTSTRAP generation (no dict
linked yet = priming effectively off). Fix: `gen_winlink_dict.cc` now calls
`set_dict_priming(false)` on both the compressor AND the self-check RX, so the blob
is the fresh-cold form the firmware actually decodes. Verified: the enriched dict
primes `[DICT] Primed v1: raw=2643 compressed=1303` with zero decode failures.

Empirical symmetry proof (this session, since-removed scratch
tmp_prime_symmetry.cc): a compress-warmed TX and a decompress-warmed RX, AND two
decompress-warmed peers, all compress a subsequent message to the SAME 60-byte
wire and decode it bit-exact. Decompress-on-both-sides is the production routine.

## §2. Producers of the streaming context state

The streaming context is {PPMd model (`ppmd_ctx`, `ppmd_model_warm`,
`ppmd_model_initialized`), zstd prefix (`zstd_prefix`/`_len`), `stream_batch_count`,
and NEW `dict_version_active`}. Producers (mercury_compress.cc unless noted):

| # | Producer | Writes |
|---|----------|--------|
| P1 | `streaming_enable()` | allocs prefix, clears warm/init/`dict_version_active`, THEN calls `prime_with_dict()` |
| P2 | `prime_with_dict()` | decompress(dict)→PPMd model; commit(dict)→prefix; sets `dict_version_active=WINLINK_DICT_VERSION` |
| P3 | `streaming_commit()` | appends to zstd prefix, sets `ppmd_model_warm`, `stream_batch_count++` |
| P4 | `ppmd_compress()` / `ppmd_decompress()` | Ppmd8_Init on first/post-reset use, sets `ppmd_model_initialized`; advance model per symbol |
| P5 | `ppmd_model_reset()` | clears `ppmd_model_initialized` (lock-step at non-PPMd batches) — UNCHANGED by this fix |
| P6 | `streaming_reset()` | Ppmd8_Init RESTART, clears warm/init, prefix_len=0, **NEW: `dict_version_active=0`** |
| P7 | `streaming_disable()` | Ppmd8_Init, clears warm/init, **NEW: `dict_version_active=0`**, frees prefix |
| P8 | `compress_block()` | writes header incl **NEW: dict-tag bits 5-7 = `dict_version_active`** |

ARQ-layer producers that drive the above (unchanged call sites, new side effect via
priming inside `streaming_enable`):
- arq_responder.cc:2214, 2939, 4042 — `compressor.streaming_enable()`
- arq_commander.cc:3801, 4258, 9386 — `compressor.streaming_enable()`
- arq_common.cc:865, 8663, 8748; arq_responder.cc:746; arq_commander.cc:12183 —
  `compressor.streaming_reset()` (now also clears `dict_version_active`)

## §3. Consumers of the streaming context state

| # | Consumer | Reads / assumes |
|---|----------|-----------------|
| C1 | `compress_block()` PPMd-only gate | `streaming_active && ppmd_model_initialized` → after priming, model IS initialized (P2 ran decompress→Init) so TX adopts PPMd-only mode on a primed stream. Correct: RX is identically primed. |
| C2 | `decompress_block()` version-lock | **NEW**: reads frame dict-tag (bits 5-7). If `is_streaming_frame && frame_dict_ver != dict_version_active` → `streaming_reset()` + return -1 (fail-safe). Runs BEFORE any model touch. |
| C3 | `decompress_block()` desync branch | `!is_streaming_frame && ppmd_model_warm` → reset. After priming `ppmd_model_warm` is true, so a COLD (un-primed/tag-0 non-streaming) peer frame trips this → RX drops to cold → decodes fresh frame. Verified safe (reverse mismatch). |
| C4 | `decompress_block()` CRC16 | `compress_crc16(plaintext)` vs header CRC. Second line of defense for any residual desync. |
| C5 | ARQ RX `copy_data_to_buffer` (arq_common.cc:8624) | `decompress_block` return >0 ⇒ push + `streaming_commit`; <=0 ⇒ `streaming_reset` + push RAW. A version-mismatch (-1) routes here → raw fallback, NO corruption. |
| C6 | ARQ ratio EMA (arq_common.cc:8651) | `dec_size / comp_payload`. Unaffected (priming only changes payload size, not the math). |
| C7 | GUI compression-algo indicator (`g_gui_state.compression_algo`, stored at `arq_common.cc` RX + `arq_commander.cc` TX; read at `gui_main.cc` as `1=PPMd / 2=zstd / else RAW`) | **NEW (added in integration audit).** Reads the algo nibble of the header byte for display only. The dict stamps the version into bits 5-7, so a primed PPMd byte (`0x25`) no longer equals `1` → the indicator mislabeled every primed frame as **RAW**. **FIX (integration):** both store sites mask `comp_data[0] / comp_buf[0]` with `COMPRESS_ALGO_MASK` (0x03) before `.store()`, so the display reflects only the algo nibble. Cosmetic, `#ifdef MERCURY_GUI_ENABLED` (headless RPi unaffected, byte-identical); the wire/decode path (C2/C4, `mercury_compress.cc:738`) already masked correctly, so round-trip integrity was never affected. This consumer was missed by the original §3 audit. |

## §4. Valid states (esp. the pre-producer default)

- BEFORE `streaming_enable`: `streaming_active=false`, `dict_version_active=0`,
  prefix=NULL. `compress_block`/`decompress_block` use the LEGACY 5-byte header
  (no dict tag, no CRC). Dict logic is inert. ✔ matches pre-dict baseline.
- AFTER `streaming_enable` with priming ON: `dict_version_active=1`,
  `ppmd_model_warm=true`, `ppmd_model_initialized=true`, prefix=raw dict,
  `stream_batch_count=1`. The FIRST real frame is tagged STREAMING + dict-v1.
- AFTER `streaming_enable` with priming OFF (`MERCURY_NO_DICT`, or
  `set_dict_priming(false)`, or `compression_enabled` false so enable never runs):
  `dict_version_active=0`, model un-warmed/un-init, prefix empty,
  `stream_batch_count=0`. First real frame tagged dict-0 (cold). ✔ byte-identical
  to the pre-dict baseline (the cold path).
- AFTER any `streaming_reset` (desync / raw-win / doesn't-fit / orphan / version
  mismatch): `dict_version_active=0`, cold for the rest of the session. Re-priming
  one-sided would re-desync; cold-and-stay-cold is the fail-safe.

Default-init bite check: `dict_version_active` is initialized in the ctor (=0) and
in `streaming_enable` (=0 before priming) — never read uninitialized. The dict tag
on a LEGACY (non-streaming) header is never written/read (gated on `streaming_active`).

## §5. Invariants and how the fix maintains them

- **INV-A (TX/RX model agreement)**: both sides' PPMd model + zstd prefix are
  byte-identical at every batch boundary. Priming PRESERVES this because both run
  the identical deterministic warm sequence (§1). Broken only by a dict-version
  DISAGREEMENT, which C2 detects and fails safe (no decode against a wrong model).
- **INV-B (no decode/encode into an uninitialized PPMd model — the segfault-fix
  invariant)**: PRESERVED. Priming's first model touch is `decompress_block`, which
  itself runs the segfault-fix gate (`!ppmd_model_initialized → Ppmd8_Init`). The
  `ppmd_model_reset()` lock-step (P5) is UNCHANGED; T7 re-validates mixed
  text/binary batches with the dict active (no crash, bit-exact).
- **INV-C (a non-PPMd batch leaves both sides' PPMd model in lock-step)**:
  UNCHANGED. Priming uses PPMd-or-zstd per the dict's entropy (the baked dict is
  text → PPMd), and the post-batch `ppmd_model_reset` logic is untouched.
- **INV-D (fail-safe over correctness for unknown peers)**: NEW, enforced by C2:
  any dict-version disagreement → cold fallback + raw push, never silent wrong
  bytes. A wrong dict primes a different model; decoding against it could even
  yield a wrong LENGTH — the explicit tag check stops it at byte 0, deterministically
  (not relying on a 1/65536 CRC collision being improbable).

## §6. What the fix changes (the §"five questions" answer for C2/C3)

The fix alters one consumer assumption: `decompress_block` now treats the
algo_flags top 3 bits as a dict-version tag (previously reserved=0). On a peer
running OLD firmware (pre-dict), those bits are 0 and `dict_version_active` is also
0 on the old side — so an old↔old link sees tag 0 == 0 (no change). A new↔old link:
the new side's primed frame has tag 1; the old side ignores the reserved bits and
decodes against its COLD model → CRC16 (C4) mismatches → old side resets → raw.
The new side, on receiving the old side's cold/tag-0 frame, trips C2 (1 != 0) →
resets to cold → both converge cold. No corruption either direction. (New↔new with
DIFFERENT dict versions: same C2 path, converge cold. Tested: TX-v1→RX-cold rejects
with -1; TX-cold→RX-v1 resets-then-decodes; both bit-exact-or-reject, never wrong.)

Reserved-bits caveat [verified]: the pre-dict firmware writes algo_flags as
`best_algo | (streaming? FLAG_STREAMING:0)` with bits 3-7 = 0, and reads only
`COMPRESS_ALGO_MASK` + `COMPRESS_FLAG_STREAMING`. So old firmware neither emits nor
inspects the dict tag — the new tag is backward-wire-safe.

## §7. Cross-layer regression test (CLAUDE.md requirement)

`source/compression/test_winlink_dict.cc` (`run_winlink_dict_tests()`, wired into
`mercury --test` and `--test-winlink-dict`) drives the production cl_compressor

- T3 version-mismatch fail-safe (C2/C3, both directions; never wrong bytes).
- T4 kill-switch (priming OFF ⇒ `dict_version_active=0`, cold path = baseline).
- T5 bulk no-regression (warm-carry still climbs >5x; the 3.69x bulk anchor holds).
- T6 attachment inertness (binary ⇒ raw path; primed wire ≤ cold; bit-exact).
- T7 streaming desync SAFETY with dict active (INV-B/INV-C; the segfault-fix path
  re-validated; mixed text/binary; under the production commit-on-success
  discipline, NO batch decodes to wrong bytes).

### §7.1 Pre-existing zstd-after-raw desync (NOT a dict regression) [verified]

Building T7 surfaced a PRE-EXISTING streaming-coherence scenario: the sequence
`text(PPMd) → binary(RAW) → text` can leave the next text batch chosen as **zstd**
(the raw binary batch ran `ppmd_model_reset`, so PPMd starts cold on the next text
batch and zstd-with-warm-prefix wins), and that zstd batch's CRC16 fails on the RX
(`rx_ret=-1`). This is recovered safely by the ARQ raw-fallback (arq_common.cc:8659
`streaming_reset` + push raw — NO corruption).

Verified channel-independent of the dict: the IDENTICAL sequence on the PRISTINE
segfault-fix baseline (`1f01d10`, no dict code) produces the SAME `b2 rx_ret=-1`,
same `corrupt=0 delivered=3`. The COLD path on this branch also reproduces it
identically. So the dict is NEUTRAL to this path — it neither causes nor worsens
it. The LOAD-BEARING discipline that makes it safe (and which the test now mirrors)
is **commit-on-success**: the RX commits raw to the streaming context only inside
`if(dec_size > 0)` (arq_common.cc:8642) and the TX commits pending only on ACK
(arq_commander.cc:5135 `commit_pending`). A test that commits on FAILURE (as an
early T7 draft did) manufactures a desync that production cannot reach.

This scenario is in the segfault-fix's domain (the PPMd/zstd algorithm-switch
coherence), NOT this feature's. Logged here as an OPEN observation for a possible
follow-on (force PPMd-continuation or suppress mid-stream algo-switch on a warm
zstd stream); out of scope for the dict, which only changes WHICH bytes seed the
stream, not the algo-switch logic.

Fail-before evidence: cold small-message ratios measured 1.42-1.99x (the regime the
feature must beat) via the production-linked `measure_primed` harness
(`_research/b2f_unroll_harness/`). Pass-after: primed 2.20-3.65x, aggregate VARA
edge 1.148 cold → 1.664 primed (BEAT). The version-mismatch path returns -1 (reject)
fail-before would have been a silent garbage decode without the C2 tag check.

## §8. Open questions / follow-ons

- [?] Per-form dicts (v2): ics213 lift came largely from ICS-213 scaffolding in the
  dict; a per-form-type dictionary library (radiogram, ICS-309, FSR, check-in) keyed
  off the B2F Subject `//WL2K <form>` could lift further. The version tag is 3-bit
  (8 dicts) — a natural fit for a small form-keyed library. Gated on a real-corpus
  training pass and its own bit-exact regression per dict. Universal v1 captures most
  of the gain (the scope's recommendation) and is what ships here.
- [?] Dict-version negotiation in the handshake: currently the version-lock is a
  per-frame fail-safe (converge-to-cold on mismatch). A handshake dict-id exchange
  could let mixed-version peers pick the highest COMMON dict instead of falling to
  cold. Not needed for v1 (a single universal dict; mismatch only on firmware skew),
  but the right place for a v2 form-library. Deliberately NOT added (avoids touching
  the fragile capability handshake — CLAUDE.md §2).
- Bounded beat (scope): wins on boilerplate-heavy text (forms, check-ins, short
  msgs); long free-prose and attachment-bearing traffic still ≤ parity. The dict is
  inert (never harmful) on those — T6 confirms.

- **CRLF**: real `.mime` is uniformly CRLF. The dict is now CRLF too, so its scaffold

  LF-normalized variant on real traffic (primed edge 1.339 vs 1.329).
- A trimmed genuine XML scaffold (real `<form_parameters>` + the common `<variables>`
  header: msgto/msgcc/msgsender/…/msgseqnum) is kept — small priming cost, helps the
  raw-XML paths and the few P2P/text-mode forms. Proven RFC822/B2F headers retained.

Result: raw 2643 → **3703 B**, compressed 1303 → **1400 B**. `WINLINK_DICT_VERSION=1`
unchanged. Generator self-check PASS (un-primed decode(COMPRESSED)==RAW).

## §11. v2 — ZDICT-trained generalizable dictionary on a held-out split (2026-06-18)

v1 (§9/§10, 3703 B) was HAND-CURATED boilerplate. v2 replaces it with a
ZDICT-`--train`-mined dictionary built on a DISJOINT train/test split of 79 genuine
transmitted `.mime` files (`_dictwork/`, manifest `split_manifest.json`,
reproducible `split.py`). Method:

1. `zstd --train _dictwork/train/*.mime --maxdict=12000` mines the highest-frequency
   substrings of real traffic — it found generalizable Winlink boilerplate the
   hand-curation MISSED: METAR/TAF aviation-weather format, NWS forecast tables
   (`FCST`/day-grids), Saildocs footer, the email-quote prologue
   (`On <date> at <time> ... wrote:`), and a richer MIME envelope.
2. **PII-SCRUB (honesty-critical):** the ZDICT also memorizes operator-specific
   tokens (`KG7VSN` 5×, `Kameron Markham`, the Tolstoy sig quote, the home grid).
   These are STRIPPED line-by-line (`cand/scrub_zd_12000.txt`, 0 residual PII
   asserted) so the shipped dict is a UNIVERSAL generalizer, not a memorizer of one
   ham's traffic.
3. The scrubbed ZDICT content is concatenated with the v1 form scaffolding
   (ICS-213/radiogram XML — universal, ZDICT under-weighted it) + the ordered
   envelope LAST (closest to the message). Final = `tools/winlink_dict_v2.txt`,
   15191 B raw / 4657 B baked, regenerated via `gen_winlink_dict` (self-check PASS).
   `WINLINK_DICT_VERSION` bumped 1→2.

### §11.3 Honesty caveats

The held-out split is SAME-OPERATOR (one KG7VSN install). PII-scrubbing removes
verbatim operator tokens, but the ZDICT's *generalizable* boilerplate is still

the 2.272 tiny figure is an honest same-operator-deployment number; a different

2.5-3× memory target holds per-message on the cleanest small messages (3.0-3.5× each)
but the honest aggregate is 2.272 (tiny) / 1.648 (form-diluted full).
